# 역사 채용노트 · Android 0.1.0

중·고등학교 **역사 기간제교사** 채용 공고를 휴대폰에서 모아보는 개인용 Android 앱입니다.
서울·경기를 기본 지역으로 보고, 동경한국학교를 예외로 포함합니다. 일반사회·도덕·윤리와 시간강사는 대상에서 제외합니다.

## 구현한 기능

- 공고 목록 / 확인 필요 / 관심 공고, 학교·지역·제목 검색
- 서울교육일자리포털, 경기도교육청, 동경한국학교 기본 등록
- 게시판 추가·수정·삭제·일시중지, 일반 게시판 링크 읽기 시험 기능
- 수동 확인, 한국 시간 정오 12시·오후 6시 자동 확인 (설정에서 변경)
- 신규·수정 공고의 기기 자체 알림, 중복 알림 방지
- HTML 본문, HWP 5 / HWPX / 텍스트 PDF 읽기
- 게시판별 마지막 성공 시각 / 부분 확인 / 실패 원인 표시
- JSON 백업·복원, 진단 내용 복사, WebView에서 현재 페이지 HTML 저장
- 기기 내부 저장. AI 계정, AI API 키, 운영 서버, 텔레그램 불필요

## 검증 상태 — 반드시 읽어 주세요

**아직 실서비스 검증을 마친 앱이 아닙니다.** 이 작업 환경에서는 외부 사이트 직접 요청과 Gradle/Android SDK 다운로드가 차단되어 있습니다.

검증한 것:

- 운영 코드의 순수 Java 수집·분류·문서 읽기·예약 계산 모듈 컴파일
- `python3 tools/test_core.py`의 합성 문서/게시판을 사용한 회귀 검사
- 모든 Java 파일 문법 분석, XML/YAML 구성 구문 검사

아직 검증하지 못한 것:

- Android SDK에 의한 앱 전체 컴파일 / Android Lint / APK 설치·실행
- 실제 세 게시판의 HTML 구조, 페이지 이동, 첨부 다운로드에 대한 실기기 수집
- 휴대폰 절전 상태에서의 실제 자동 확인·알림

기본 사이트용 어댑터에는 알려진 상세 URL 규칙과 일반적인 HTML·onclick 패턴을 적용했습니다. 실제 사이트 전체 DOM을 확보하지 못했으므로 최초 설치 후 게시판별 수정이 필요할 수 있습니다. 사이트 전용 JSON API나 JavaScript를 자동으로 역분석하지 않습니다. 구조를 해석하지 못하면 빈 성공 결과 대신 오류를 표시합니다.

## APK 만들기: GitHub Actions

별도 서버를 운영할 필요 없이 APK를 만들 때만 빌드를 실행합니다.

1. 새 GitHub 저장소에 **이 폴더의 내용 전체**를 업로드합니다. `.github/workflows/build-apk.yml`도 포함해야 합니다.
2. 저장소의 **Actions → Build APK → Run workflow**를 실행합니다. `main`/`master`에 올릴 때도 실행됩니다.
3. 성공한 실행의 **Artifacts → history-jobs-0.1.0-apk**를 다운로드합니다.
4. 다운로드한 ZIP 안의 `history-jobs-0.1.0.apk`를 Android 휴대폰에서 엽니다.
5. 해당 파일 앱/브라우저의 APK 설치를 허용한 뒤 설치합니다. 앱을 한 번 열어 알림 권한을 허용합니다.

워크플로는 표준 Ubuntu runner를 사용합니다. 개인 저장소를 쓴다면 계정의 무료 Actions 잔여 사용량 안에서 실행하세요. 유료 실행 환경이나 외부 유료 서비스를 설정하지 않습니다.

생성되는 것은 개인 테스트용 debug APK입니다. 같은 서명으로 후속 버전을 설치할 수 있도록 GitHub의 debug signing key 캐시를 사용하지만, 캐시가 제거되면 키가 달라질 수 있습니다. 이때는 기존 앱에서 JSON 백업을 먼저 내보내고 재설치 후 복원해야 합니다. 장기 사용 시 본인 소유 서명키를 설정하는 편이 좋습니다.

## Android Studio에서 빌드

- Android Studio, JDK 17 이상
- Android SDK Platform 35 / Build Tools 35.0.0
- 최초 의존성 다운로드를 위한 인터넷 연결

폴더를 Android Studio에서 열고 Gradle 동기화 후 `app`을 실행합니다. 명령줄은:

```sh
./gradlew :app:assembleDebug :app:lintDebug
```

결과: `app/build/outputs/apk/debug/app-debug.apk`

## 처음 사용할 때

1. 공고 모아보기에서 **지금 확인**을 누릅니다.
2. **게시판** 탭에서 세 사이트의 마지막 성공 시각과 메시지를 확인합니다.
3. **역사 기간제**와 **확인 필요** 목록을 함께 살펴봅니다.
4. 설정에서 테스트 알림을 보내고 필요하면 배터리 설정을 조정합니다.

실패한 사이트는 게시판 카드의 **게시판 진단 · 페이지 열기**로 엽니다. 사이트가 휴대폰 브라우저에서는 정상이라면 **현재 페이지 HTML 저장**으로 진단 파일을 저장해서 수정 요청에 첨부할 수 있습니다. 로그인한 페이지를 저장하면 개인 정보가 포함될 수 있으므로 공고 게시판에서만 사용하세요.

## 동작과 제한

- Android 8.0(API 26) 이상을 대상으로 작성했습니다.
- WorkManager는 정확한 시각 실행을 보장하지 않습니다. 기기 강제 종료, 절전, 네트워크 상태에 따라 확인이 늦어질 수 있습니다.
- 시간대는 기기 설정과 관계없이 Asia/Seoul입니다.
- 서버 없는 방식이므로 PC와 휴대폰의 데이터가 자동 동기화되지는 않습니다.
- 한 번의 게시판 확인은 최대 20페이지·100개 본문·약 90초를 목표로 제한합니다. 진행 중 요청은 timeout까지 더 걸릴 수 있습니다. 남은 본문은 이후 확인 때 우선 읽습니다. 페이지 범위를 넘으면 부분 확인으로 표시합니다. 전체 게시판 무누락을 보장하지 않습니다.
- 일반적인 목록 페이지 링크·onclick을 지원합니다. 동적으로만 생성되는 공고 목록, 로그인, CAPTCHA, 다운로드 전용 JavaScript, 다른 구조의 게시판은 수정이 필요할 수 있습니다.
- PDF는 텍스트가 있는 40페이지 이하 문서를 읽습니다. 이미지 스캔 PDF의 OCR은 포함하지 않았습니다.
- 한글 문서의 표는 글자만 추출합니다. 암호화·배포용 HWP와 HWP 3.x는 확인 필요로 남습니다.
- 읽지 못한 새 공고는 확인 필요로 남기며, 기존에 확인한 공고는 일시적 조회 실패로 덮어쓰지 않습니다.
- ‘역사 기간제’는 모집 조건의 자동 분류이며 개인의 지원 자격 충족 여부를 뜻하지 않습니다.
- 마감일만 있고 시간이 없으면 당일 끝을 목록 숨김 기준으로 사용하되 ‘시각은 원문 확인’으로 표시합니다. 원문 시간이 우선입니다.
- 공고 ID/URL 기준 중복은 막습니다. 교육청과 학교에 서로 다른 URL로 올라온 공고의 의미상 중복 통합은 포함하지 않았습니다.
- 백업은 공고·게시판·관심 상태를 담습니다. 자동 확인 시각과 알림 설정은 기기 설정에 남습니다.
- 앱 업데이트는 APK를 새로 설치하는 방식이며 자동 업데이트 기능은 없습니다.

## 개발·수정

```sh
python3 tools/test_core.py
```

Android SDK 없이 Java 17 이상만으로 핵심 모듈을 검사합니다. 테스트의 게시판과 문서는 실제 사이트를 캡처한 것이 아니라 동작 검증용 합성 입력입니다.

| 파일 | 역할 |
| --- | --- |
| `core/BoardParser.java` | 사이트별 링크·목록·본문 해석 |
| `core/Collector.java` | 페이지 순회·첨부 읽기·오류 보존 |
| `core/Classifier.java` | 과목·채용 형태·학교급·접수 마감 분류 |
| `core/HanText.java` | HWP/HWPX 글 추출 |
| `core/Schedule.java` | 한국 시간 예약 계산 |
| `Store.java` | 원자적 로컬 저장·관심 상태·백업 |
| `SyncEngine.java` | 수집 실행·PDF 읽기·알림 |
| `CheckWorker.java` | 자동 확인 예약 |
| `MainActivity.java` | 공고·게시판·설정 화면 |
| `InspectActivity.java` | 진단용 게시판 열기·HTML 저장 |

Java 파일 경로는 `app/src/main/java/kr/personal/historyjobs/` 기준입니다.
