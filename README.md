## 0.1.12 변경 사항

- 요청한 과학고·외고 14곳을 지정한 키워드로 자동 등록합니다. 기존에 같은 게시판이 있으면 중복 추가 없이 요청한 키워드를 한 번 적용하고, 이후 사용자가 변경·삭제한 설정은 보존합니다.
- `교사 AND 공고`, `교사 AND 채용`처럼 AND 조건을 지원합니다. AND가 OR보다 먼저 적용되며 연산자 앞뒤에는 공백이 필요합니다. 기존 쉼표·줄바꿈은 OR입니다.
- 세종과고·한성과고·경기북과고·명덕외고·고양외고·김포외고: 교사. 서울외고: 교원. 이화외고·한영외고: 교사 OR 교원. 과천외고: 채용. 동두천외고·수원외고: 교사 AND 공고. 성남외고: 교사 채용 OR 교원 선발. 안양외고: 교사 AND 채용.
- 과천외고는 첫 화면 대신 실제 공지사항 주소를 등록합니다. 명덕·김포의 레거시 게시판, 이화·수원의 GNUboard 형식 및 한성과고의 이전 BBS ID 형식을 지원합니다.
- 게시물 URL의 페이지·검색 매개변수로 인한 중복을 정리하고, 명덕·김포의 잘못된 UTF-8 응답 헤더는 HTML에 선언된 한글 인코딩으로 보완합니다.
- 학교 제목의 올해·다음해 학년도 조건과 게시일 범위는 유지합니다. 첨부파일은 수집하지 않습니다.
- 확인 환경에서 고양외고는 HTTP 400, 수원외고는 연결 시간 초과를 반환해 실제 목록·본문 수집은 검증하지 못했습니다. 게시판·키워드는 등록되며 접속 실패를 정상 수집으로 표시하지 않습니다.

## 0.1.11 변경 사항

- 서울교육일자리포털 정규교원(보통교과/도덕사회과)과 경기도교육청 사립학교 교원정규채용을 추가합니다. 기존 설치도 한 번 자동 추가하며, 이미 같은 채용 유형으로 등록한 게시판은 중복 추가하지 않습니다. 이후 삭제한 게시판은 재생성하지 않습니다.

- 서울·경기 교육청의 기간제/정규교원 공고는 제목 키워드에 일치하거나, 공고별 직무분야·과목(담당업무)에 ‘역사’가 있으면 수집합니다. 서울은 직무분야가 교과군, 과목이 세부 교과로 나뉘어 있어 둘 다 확인합니다.
- 공고 상세에서 읽어 온 직무분야·과목을 표시하고 백업에 보존합니다. 본문과 첨부파일을 과목 선별에 사용하지 않습니다.
- 개별 학교의 제목·학년도 기준 및 기존 게시일 범위는 유지합니다.

## 0.1.10 변경 사항

- 날짜가 확인된 일반 게시물이 모두 기존 수집 범위(작년 1월 1일)보다 오래된 페이지에 도달하면 정상 종료합니다. 이 종료 처리를 모든 게시판에 적용합니다.
- 고정 공지는 과거 구간 판정에서 제외합니다. 게시일 미상 또는 수집 기간의 글이 섞여 있으면 탐색을 계속합니다.
- 이전·마지막 페이지로 건너뛰지 않고 다음 페이지를 순서대로 읽습니다. 서울 학교 게시판은 공개 목록 요청당 50개를 읽어 요청 수를 줄입니다.
- 필터 창에서 지역·게시판을 함께 선택할 수 있습니다. 여러 게시판 선택, 취소, 전체 초기화 및 선택 저장을 지원합니다. 전체 게시판 모드에는 앞으로 추가할 게시판도 자동 포함합니다.
- 네트워크 실패나 실제 확인 한도 도달은 여전히 별도 안내합니다. 오래된 구간에 도달한 정상 종료는 범위 제한 메시지를 표시하지 않습니다.

## 0.1.9 변경 사항

- 수집 키워드에 `OR` 또는 `or`를 사용할 수 있습니다. 예: `교원 선발 OR 교원 임용 OR 기간제`. OR 앞뒤에는 공백을 넣습니다. 쉼표·줄바꿈도 계속 지원하며 하나라도 제목에 있으면 일치합니다.
- 개별 학교 게시판은 제목에 올해 또는 다음해 학년도가 있어야 수집합니다. 2026년 기준 `2026학년도` 또는 `2027학년도`입니다. 서울·경기 교육청 채용 포털은 이 추가 조건에서 제외합니다.
- 기존 게시일 범위(작년~올해)는 그대로 적용합니다. 학년도와 게시일은 각각 확인합니다.
- 기존 저장 공고도 앱을 열거나 백업을 복원할 때 다시 판정합니다. 조건을 벗어난 학교 공고는 목록과 알림에서 제외하며, 읽음·즐겨찾기 정보는 보존합니다.
- 서울과고 추천 키워드: `교원 선발 OR 교원 임용 OR 기간제`. ‘교원 임용후보자 공개선발’은 두 번째 문구와 일치합니다.

## 0.1.6 기간·키워드·지역 필터

- 학교·교육청 구분 없이 실제 등록일로 작년/올해 게시물만 선정합니다. 한국 시간의 현재 연도가 바뀌면 범위도 자동으로 이동합니다. 수집 시각·접수 마감·제목 속 학년도는 등록일을 대신하지 않습니다.
- 게시일 미상은 제외하며, 수집 중 해당 키워드의 글에서 게시일을 찾지 못하면 게시판 상태에 이유를 표시합니다.
- 기존 목록과 관심 목록, 알림에도 같은 기간을 적용합니다. 이전 버전에 게시일이 저장되지 않았던 글은 숨긴 뒤 **지금 확인**으로 등록일을 갱신합니다. 원본 기록/관심/읽음 상태는 기간 필터 때문에 삭제하지 않습니다.
- 동경 게시판은 다음 페이지를 순서대로 읽습니다. 오래된 날짜 구간에 도달하면 정상 종료하며 마지막 페이지로 먼저 뛰어가지 않습니다. 실제 요청 오류나 안전한도 초과는 계속 일부 확인으로 표시합니다.
- **게시판 → 수정 → 수집 키워드**에서 쉼표 또는 줄바꿈으로 1~30개를 입력합니다. 하나라도 제목에 있으면 선정하며 공백·영문 대소문자를 구분하지 않습니다. 빈 키워드 전체 수집은 허용하지 않습니다.
- 기존 게시판의 초기 키워드는 서울/경기 교육청 ‘역사’, 동경 ‘교원 채용’·‘교직원 채용’, 그 밖의 기존 학교 ‘역사’·‘교원 채용’·‘교직원 채용’입니다. 새 게시판은 ‘역사’로 시작하며 자유롭게 수정합니다. 사용자 설정은 기본 규칙을 대체합니다.
- 키워드를 바꾸면 저장된 공고도 다시 분류합니다. 아직 저장되지 않은 다른 키워드 글은 **지금 확인**으로 가져옵니다. 키워드/지역을 바꾸는 동안 끝난 이전 설정의 수집 결과는 무시합니다.
- 지역은 경기·서울·기타 지역입니다. 이전 ‘동경’ 및 구분되지 않는 옛 지역은 기타 지역으로 전환합니다.
- 공고 개수 오른쪽의 ‘필터’에서 지역을 여러 개 선택할 수 있습니다. 관심 공고에도 적용되며 선택 상태는 기기에 저장됩니다. 지역별 화면 필터는 알림 지역을 제한하지 않습니다.
- 게시판별 키워드/지역, 공고의 확인된 게시일은 백업·복원에 포함됩니다.


## 0.1.5 본문 열람과 학교 게시판 조건 확대

- 앱 이름·갈색 테마·승인된 런처 아이콘·개인 서명키는 유지합니다.

## 업데이트

0.1.1·0.1.2·0.1.3·0.1.4·0.1.5·0.1.6·0.1.7 → 0.1.8은 같은 고정 서명으로 덮어 설치할 수 있습니다.

0.1.0의 임시 서명키 캐시 경로가 실제 생성 경로와 달라 키가 남지 않았습니다. 따라서 **0.1.0에서 0.1.1로는 덮어 설치할 수 없습니다.**

1. 기존 앱에 남길 기록이 있으면 **설정 → 백업 파일 저장**을 먼저 실행합니다.
2. 기존 앱을 삭제하고 새 APK를 설치합니다.
3. **설정 → 백업 가져오기**로 게시판·관심·읽음 기록을 복원합니다. 알림 권한과 자동 확인 시각은 다시 확인하세요.
4. ‘지금 확인’으로 새 목록을 가져옵니다.

0.1.1부터는 별도로 보관하는 고정 개인 서명키로 제공 APK를 서명합니다. 같은 키를 사용하는 후속 업데이트는 덮어 설치할 수 있습니다.

새 기준과 관계없는 이전 공고는 화면에서 제외하지만, 원본 저장 항목과 관심·읽음 상태는 지우지 않습니다. 백업에도 기록은 남습니다.

## 설치·빌드

Android 8(API 26) 이상을 대상으로 작성했습니다. APK를 휴대폰에서 열고 필요하면 해당 브라우저/파일 앱의 설치를 허용합니다. 앱을 열고 알림 권한을 허용한 뒤 ‘지금 확인’을 누릅니다.

GitHub **Actions → Build APK**의 성공한 실행에는 **history-jobs-0.1.8-unsigned** artifact가 있습니다. 이것은 서명 전 APK와 공식 Android apksigner 도구입니다. 이 대화에서 제공하는 설치용 APK는 해당 빌드에 개인 서명을 추가한 파일입니다. 서명 전 APK는 설치용이 아닙니다.

Android Studio 또는 JDK 17 + Android SDK 35 환경:

```sh
./gradlew :app:assembleDebug :app:lintDebug
```

결과: `app/build/outputs/apk/debug/app-debug.apk`

워크플로는 표준 Ubuntu runner를 사용합니다. 개인 저장소를 사용하면 계정의 무료 Actions 잔여 사용량 안에서 실행하세요. 앱 자체의 운영 서버는 없습니다.

서명키와 비밀번호는 공개 저장소·Actions artifact에 올리지 않습니다. 향후 APK를 서명할 때는 별도로 보관한 개인 키 파일과 설정을 사용합니다.

```sh
python3 tools/sign_apk.py --input history-jobs-0.1.8-unsigned.apk --output history-jobs-0.1.8.apk --signer apksigner.jar --credentials /개인경로/signing.json
```

`signing.json`은 같은 폴더의 `history-jobs.p12` 경로, 키 별칭과 암호를 담는 개인 설정 파일입니다. 배포 전 인증서 지문이 이전 제공 APK와 같은지 확인합니다. 키 보관본은 공개 저장소에 포함하지 않습니다.

## 제한

- WorkManager는 정확한 시각 실행을 보장하지 않습니다. 절전·강제 종료·네트워크 상황의 영향을 받습니다.
- 기기 시간대와 관계없이 Asia/Seoul 기준입니다.
- 한 번에 최대 20페이지, 약 35초의 목록 확인 범위를 둡니다. 진행 중인 요청은 timeout까지 더 걸릴 수 있습니다. 한도를 넘으면 부분 확인으로 표시합니다.
- 각 게시판의 제목 조건에 맞지 않는 공고는 놓칠 수 있습니다. 본문 열람은 가능하지만 본문·첨부를 통한 보완 선정은 하지 않습니다.
- 일반 게시판은 시험 지원입니다. 등록일 열/메타데이터가 다른 구조에서는 어댑터 보완이 필요하며, 날짜를 추측해서 최근 공고로 처리하지 않습니다. 로그인·CAPTCHA·다른 게시판 구조도 지원이 제한됩니다.
- 동경한국학교는 간헐적으로 사용제약 안내를 반환한 이력이 있습니다. 앱에서는 오류로 표시합니다.
- 목록에 마감 시각이 없으면 날짜 끝을 숨김 기준으로 사용하고 ‘시각은 원문 확인’으로 표시합니다.
- URL/공고 ID 기준 중복을 막습니다. 서로 다른 URL의 의미상 중복은 합치지 않습니다.
- 공고가 목록에서 사라졌다고 저장 기록을 즉시 삭제하지 않습니다.
- 백업은 공고·읽어 온 본문·게시판·관심 상태를 포함합니다. 알림·확인 시각은 해당 기기의 설정에 남습니다.
